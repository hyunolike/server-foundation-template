# 0007. 본문 없는 성공은 204로 내보내고 봉투를 쓰지 않는다

- 상태: 수용됨
- 관련: [설계 문서 §6.5](../design/architecture.md)

## 맥락

"모든 JSON 응답이 같은 네 개의 키를 가진다"는 규칙에는 예외가 하나 생긴다. 핸들러가 본문을 만들지 않으면 메시지 컨버터가 아예 호출되지 않아 `ResponseBodyAdvice.beforeBodyWrite`가 돌 기회가 없다.

구현 중에 확인했다 — 반환 타입을 `Any?`로 두고 `null`을 돌려줘도 200에 **빈 본문**이 나간다. `"data": null`인 봉투가 아니다.

대안은 삭제 API가 200 + `"data": null`을 반환하도록 컨트롤러가 뭔가 non-null을 만들어 내는 것이었다.

## 결정

`204 No Content`로 내보내고 봉투를 쓰지 않는다. 봉투 규칙의 유일한 예외로 문서에 적고 테스트로 고정한다.

## 결과

- "키는 항상 존재한다"를 지키려고 없는 데이터를 지어내지 않는다.
- 클라이언트는 204를 본문 없음으로 처리해야 한다. 상태 코드만 보면 되므로 분기 비용은 작다.
- `EnvelopeContractTest`가 이 예외를 고정한다 — 204이고 본문이 비어 있어야 통과한다. 누군가 200 + 빈 봉투로 바꾸면 테스트가 깨진다.
