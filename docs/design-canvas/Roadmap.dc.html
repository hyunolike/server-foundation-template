BUILD ORDER · M0~M4 완료
만드는 순서와 끝나는 기준
각 단계는 “코드를 썼다”가 아니라 확인 가능한 사실로 끝난다. M0~M4 는 구현을 마쳤고, 각 완료 기준은 테스트로 고정돼 있다.
단계
이름
산출물
완료 기준
M0 ✓
골격
Gradle 멀티모듈 6개, 버전 카탈로그, ktlint/detekt, CI 워크플로 스켈레톤
빈 모듈 상태로 ./gradlew build가 CI에서 통과한다
M1 ✓
계약
foundation-core — ApiResponse, PageResponse, ErrorCode, BusinessException, 공통 코드
의존성 그래프에 Spring이 없고, 에러 코드 중복·상태 누락을 잡는 계약 테스트가 돈다
M2 ✓
표준화
foundation-web + observability — 봉투 Advice, 예외 핸들러, /error, TraceId, 마스킹
성공 · 검증 실패 · 미처리 예외 · 매핑 없는 URL 네 응답이 모두 같은 봉투로 나온다
M3 ✓
문서화
foundation-docs — 봉투 스키마 커스터마이저, @ApiErrorCodes, Swagger UI 프리셋
Swagger UI에서 200 응답이 봉투로, 404가 실제 에러 코드로 보인다
M4 ✓
검증
REST Docs 지원, 스펙 응답 검증기, verifyOpenApi / diffOpenApi
응답 필드를 하나 바꿔 보면 문서 갱신 없이는 CI가 실패한다
M5
템플릿화
GitHub template 설정, 패키지명 치환 스크립트, README · ADR · 용어집
새 저장소를 만들어 첫 엔드포인트와 문서를 얻기까지 10분 안에 끝난다
이번 설계의 범위 밖 — 훅 지점만 열어 둔다
인증·인가 구현 데이터 접근 계층 선택 (JPA / jOOQ / Exposed) 배포 · 인프라 메시징 · 비동기 멀티테넌시
